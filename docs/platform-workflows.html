1. CI Pipeline (Авто-Тестирование & Линтинг)
Автоматический
Запускается при каждом git push в ветки main, dev, feat/**, fix/** или при создании Pull Request. Гарантирует абсолютную чистоту монорепозитория перед слиянием.
1. Установка окружения: Node.js 22, pnpm 11, frozen lockfile verification.
2. Type Check: pnpm type-check (tsc без эмита на backend, frontend, shared).
3. Строгий Линтер: pnpm lint (ESLint с флагом --max-warnings=0).
4. Тесты фронтенда: Vitest (1,005 тестов в 75 сьютах).
5. Тесты бэкенда: Jest (830 тестов в 74 сьютах).
6. Monorepo Build: Turbo build (Vite production bundle + NestJS production build).

2. CD Production Deployment (Hostinger VPS)
Zero-Downtime
Срабатывает автоматически после успешного прохождения CI Pipeline на ветке main. Выполняет безопасный деплой по SSH на боевой сервер.
1. Триггер & Проверка: Ожидание статуса success от CI Pipeline.
2. SSH Handshake: Подключение к VPS через зашифрованные секреты VPS_HOST, VPS_SSH_KEY.
3. Синхронизация кода: git fetch origin main && git reset --hard origin/main.
4. Настройка фаервола: UFW & iptables правила для портов 80, 443, 22.
5. Docker Build & Up: docker compose -f docker-compose.prod.yml up -d --build.
6. SSL & Let's Encrypt: Проверка валидности сертификата alanyaholidays.com, автогенерация/обновление и reload Nginx.

Безопасность • NestJS + Supabase RLS
Двухуровневая Защита Ролей & RLS
Zero Leaks
Ни один неавторизованный пользователь не может получить доступ к административным операциям ни через UI, ни напрямую через REST API.
1. Уровень API (NestJS): Контроллер @UseGuards(AuthGuard) проверяет JWT, извлекает req.user.id и верифицирует роль admin в БД.
2. Уровень Базы Данных (RLS): Row Level Security в PostgreSQL запрещает чтение и изменение чужих строк.
3. Хранимые процедуры (RPC): Выполняются в режиме SECURITY DEFINER с явным SET search_path = public.
Supabase RLS NestJS AuthGuard SECURITY DEFINER

DevOps • scripts/backup-db.sh & Cloudflare R2
Автономные Бэкапы БД & GFS Ротация
SHA-256 Verified
Автоматизированная система резервного копирования PostgreSQL с выгрузкой в Cloudflare R2 / S3, GFS ротацией и 3-уровневой валидацией восстановления.
1. Создание дампа: pg_dump сжатие в .sql.gz + генерация SHA-256 контрольной суммы и .meta.json.
2. Удаленная репликация: Отправка в S3-совместимое хранилище (Cloudflare R2).
3. GFS Pruning (7 дней + 4 недели): Очистка старых архивов с чистой целочисленной арифметикой дат (JDN).
4. 3-Tier Dry-Run Restore: Инструмент scripts/restore-db.sh проверяет целостность без повреждения продакшн-данных.
